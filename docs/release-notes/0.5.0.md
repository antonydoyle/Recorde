# Recorde 0.5.0

Changes since 0.3.10. The 0.4.0 release candidate was not published; its
changes are included here.

## Themes and graph

- Ten single-mode themes based on popular VS Code themes: Monokai, Tokyo Night,
  Dracula, One Dark Pro, Nord, Gruvbox Dark and SynthWave '84 (dark), and GitHub
  Light, Solarized Light and Catppuccin Latte (light). Each sets its own light or
  dark mode; colours are adjusted where needed so text meets WCAG AA contrast.
  The colour palette list is grouped into Light and dark, Dark and Light.
- Graph nodes show the author's initials in the branch colour, outlined in a
  colour unique to each person. Lines are no longer hidden under a selected
  row, and the graph column widens to fit busy histories until you resize it.
- Long branch names in the sidebar end in an ellipsis and show in full on hover.

## Interface

- Text fields match button heights; radio buttons show a clear selected state.
- Default shortcuts for Open (Ctrl+O), Clone (Ctrl+Shift+O) and Settings
  (Ctrl+,). Diff line hints say exactly what a click will do.
- The conflict editor opens centred; the theme list shows more entries at once.
- A Git readiness check reports whether the installed Git is usable.

## Repository workflows

- Select graph commits with Ctrl/Command-click or Shift-click, then confirm a
  cherry-pick or revert, compare two commits, or review an interactive squash or
  bulk-drop plan. Confirmed sequences retain exact repository, branch, HEAD and
  commit targets and recheck them when queued work starts.
- Use visible Undo and Redo controls to walk supported local recovery snapshots.
  Restores check for later repository edits; they do not reverse remote changes.
- Choose ordinary, no-fast-forward, fast-forward-only or squash merges. Advance
  an eligible local branch to its upstream without checking it out.
- Initialize and finish Git Flow features, releases and hotfixes. Required
  branches and release tags are checked before merging; conflicting tags fail.
- Check out remote tracking branches, create branches from refs, reset to a
  selected commit, recover deleted branches and finish bisect sessions in-app.
- Browse branches in collapsible remote groups. Graph branch/tag labels select
  their commit on click and offer reference-specific menus; double-click a
  branch label to check it out.
- Include untracked files in a stash, or stash a single tracked or new file.
- Initialize repositories with a default branch, README, ignore and licence
  templates. Browse or search repositories using a selected GitHub/GitLab
  account, choose HTTPS/SSH cloning, or confirm a personal fork.

## Accounts and SSH

- Save profiles with Git identity, an optional signing key and saved provider
  account choices. Apply global account defaults or per-repository overrides;
  optionally restore captured colours and external editor/terminal/diff/merge
  commands when applying a global profile. Tokens remain in the OS vault.
- An explicit HTTPS clone username overrides a global account default. A username
  conflicting with an explicit per-repository account binding still fails.
- Generate OpenSSH Ed25519 key pairs in process, optionally encrypted with a
  passphrase. Generation no longer puts passphrases in subprocess arguments,
  environment variables or plaintext temporary files. Existing key paths are
  never overwritten; private files use restricted access.
- Copy generated public keys or upload them to supported providers. Adding an
  encrypted key to an SSH agent still requires an external terminal or askpass.

## Workspace and help

- Choose Classic light/dark or Siege21 light/dark. Siege21 light uses beige and
  orange; its dark counterpart uses orange and white on dark surfaces. Primary
  accents use `#D54329`, with readable text variants. High contrast, UI scaling
  and distinct diff/error colours remain available.
- Resize, hide and reorder graph columns, and choose relative dates, ISO dates
  or UTC date/time. Column order, visibility, date format and widths persist per
  repository; the Commit column always stays visible.
- Open searchable offline documentation from Help. Getting started, workflows,
  recovery, accounts/tools, shortcuts, themes and troubleshooting use the same
  Markdown files published in the repository wiki. Help includes navigation,
  selectable text and copyable command examples.
- Run noninteractive shell commands in up to eight repository/worktree-bound
  tabs. Each tab keeps its own input, recent history and output during the app
  session; other tabs can run independently. Stop ends a command group, closing
  a running tab asks first, and hiding the panel keeps output draining.
- Edit UTF-8 working files in-app. Saves preserve uniform CRLF endings and refuse
  to overwrite outside changes. Unsaved file edits in any repository tab block
  quitting and update restart until saved or closed through the editor.
  Undo history stays with its document; Reload asks before discarding dirty edits
  and keeps the current buffer if the file cannot be read.
- Optionally display author pictures from Gravatar or GitHub. This is off by
  default; enabling it makes requests to those services.
- Turning author pictures off and back on correctly retries canceled queued
  lookups while retaining in-flight requests and completed cached pictures.
- Discover actions in the command palette, customize keyboard shortcuts and
  retain repository navigation and layout preferences.

## Reliability and distribution

- Preserve snapshot index content when replacement refs are active, avoiding the
  cached-tree mismatch found during the parity review.
- Keep unattended Git processes supervised with cancellation and descendant
  cleanup. Command tabs bound reader buffers, pending output, retained bytes and
  per-frame processing.
- Keep provider requests scoped to the selected account and exact host. Repository
  discovery validates clone URLs, refuses redirects and does not automatically
  retry fork writes. Pending requests block an update restart.
- Keep repository shortcuts from acting behind modal editors and dialogs. Help
  navigation and graph/diff/command panel sizing have regression coverage for
  readable layouts with larger text and narrower windows.
- Verify signed update manifests and package hashes before installation.
  Update signatures are separate from executable signing and notarization.
- Windows MSVC builds require the Microsoft Visual C++ v14 x64 runtime; portable
  archives do not install it. See [platform prerequisites](../wiki/Packaging.md).

## Known limitations

- Command tabs are not terminal emulators: no PTY, interactive input or persistent
  shell state. Each command starts in its repository folder; tabs are not restored
  after restart. Use the external terminal for interactive tools. Commands entered
  directly do not automatically receive app confirmations or recovery snapshots.
- Multi-commit cherry-pick/revert require clean tracked changes and reject merge
  commits needing a mainline-parent choice. Graph bulk drop rejects root commits
  and merge-containing ranges; supported merge edits use the explicit history
  editor. All-drop linear tail plans return the branch to the reviewed upstream.
- Profiles do not create separate credential vaults or SSH sessions, and capture
  only the documented appearance/tool preferences. An empty signing key retains
  the existing setting.
- Repository browsing and personal forks cover GitHub/GitLab. Other providers
  use direct clone URLs; organization fork destinations use the provider website.
  Issue-tracker integrations beyond documented provider panels, cloud workspaces,
  team presence, Launchpad-style dashboards and AI features remain out of scope.
- Windows builds are not Authenticode-signed and macOS builds are not
  notarized. macOS has not had hands-on acceptance testing.

## Safety and reliability

- Stash Apply, Pop, Branch and Drop retain the reviewed stash identity and reject
  stale list positions. Drop requires confirmation. Removed stash commits remain
  under `refs/recorde/dropped-stashes/<fullOID>` for explicit apply/store recovery;
  stash actions are not Undo steps.
- Quit waits for background work and running command tabs. Keep working cancels
  the pending quit. Closing repository tabs or loading a workspace identifies
  unsaved editor drafts and asks before discarding them.
- Git Flow Finish reviews source/destination refs, HEAD and tags before queued
  execution, and refuses changed targets. Finished-branch deletion checks the
  required merge destinations even when its upstream is behind. Inactive-branch
  fast-forward checks every worktree, including the main worktree.
- Squash conflicts expose Continue/Abort and retain the reviewed message and
  original target. Incomplete checkpoints are not offered as usable Undo steps.
  Reset refuses a changed branch/HEAD; remote branch deletion uses a tip lease.
  Squash/Drop planning runs in a cancellable background task with streamed range
  checks and rejects stale results.
- GitLab public-key upload supports OAuth through Bearer authentication. GitHub
  upload refusals explain the SSH settings-page fallback and token permissions;
  existing browser sign-in scopes are unchanged. Global identity updates respect
  the higher priority of an existing `~/.gitconfig` over XDG configuration.
- Command tabs continue draining progressing output after shell exit instead of
  dropping the buffered final summary at a fixed two-second deadline. Idle and
  absolute cleanup limits remain bounded. Help now describes inherited credential
  helper access and the hashing/storage costs of Keep all snapshot retention.
